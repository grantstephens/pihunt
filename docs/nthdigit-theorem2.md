# Gourdon's Theorem 2: decimal digits of π with O(m) memory, reconstructed

**Status (2026-09-23): reconstructed, analysed and prototyped. It works.** The algorithm below
gets frac(10ⁿπ) with an O(m)-bit bignum working set. Its operation count is
O(n² log n · log²m · loglog m / (m log²(n/m))) word operations. For m = n^Θ(1) that is exactly
Gourdon's bound (11). The Python + gmpy2 prototype (`research/thm2/`) gives correct digits for
n up to 1.28·10⁶. It beats a C implementation of Theorem 1 at every n we tried from 4·10⁴ upward.

Legend used throughout: **[proved]** = argued in full here; **[measured]** = prototype data;
**[heuristic]/[conjecture]** = said so explicitly.

## 2. Setting (from the paper)

With M even ≥ 4 and N = ⌈(n+n₀+1)·ln10/ln(2eM)⌉ (even), Proposition 1 gives
frac(10ⁿπ) ≈ frac(B − C), error < 10^−n₀:

* B = Σ_{k<(M+1)N} (−1)^k (4·10ⁿ mod (2k+1))/(2k+1)
* C = Σ_{k<N} (−1)^k (X·s_k mod m_k)/m_k, with X = 5^(N−2)·10^(n−N+2), m_k = 2MN+2k+1 and s_k = Σ_{j≤k} C(N,j).

Theorem 1 takes M ≈ 2n/log³n, so B is cheap, and pays O(k) word operations per s_k.

## 3. Why the listed obstacles are not fatal

* **Obstacle 1 (blocking gains nothing)** is true for *naive* blocking, where you update an
  m-bit accumulator one small factor at a time (O(m/w) per factor). It is false for **binary
  splitting**. The factors (N−j+1) and j are small integers that do not depend on the block
  modulus. So you can multiply g ≈ m/log n of them together *exactly* with a product tree. That
  costs O(M(m) log m), i.e. polylog per factor instead of m/w. Then you reduce once mod Q. With
  fast multiplication, the cost per (term, j) pair drops from Θ(1) to Θ(log n·log²m/m).
  **[proved]** (§5). With schoolbook multiplication the gain collapses to a constant (≈ w/log n),
  so obstacle 1 is really "binary splitting needs subquadratic multiplication to pay off."
* **Obstacle 2 (s_k is N bits)**: never needed. We only ever hold s_t·t!, t! and N!/(N−t)!
  *modulo* the block modulus Q (m bits).
* **Obstacles 2/4 (non-invertible small primes)**: solved without factorials modulo large
  primes. Split every m_k into coprime prime-power parts and use **partial fractions**
  frac(X s/m) = Σ_q frac(X s·((m/q)⁻¹ mod q)/q) (mod 1). Each part is handled by the cheapest
  method that is valid for it (§4.3). The only primes that ever go into a big modulus are
  either > t (so t! is invertible) or are Lucas-reduced to a target below the prime.
* **Obstacle 5 (base)** doesn't apply: we keep Gourdon's formula (7) and its base-10
  compatible numerators.

## 4. The algorithm

Parameters: n, n₀, memory budget m (bits of the block modulus). Choose
M ≈ max(4, c·n/m) (c tuned so that B and C cost the same, §5.4). N follows as in §2.

### 4.1 B part
Unchanged from Theorem 1: (M+1)N modular powerings, O(1) memory.

### 4.2 The recurrence
For target t define the state
  P_t = N!/(N−t)!,  D_t = t!,  T_t = t!·s_t,   (P₀,T₀,D₀) = (1,1,1).
Step j (1 ≤ j):  P ← (N−j+1)P;  T ← j·T + (N−j+1)·P_old;  D ← j·D.
A block of steps (j₁, j₂] acts as the triple (α, δ, τ): P′ = αP, T′ = δT + τP, D′ = δD.
Triples compose as (α₁α₂, δ₁δ₂, δ₂τ₁ + τ₂α₁). That's standard binary splitting.
Then s_t ≡ T_t·D_t⁻¹ and C(N,t) ≡ P_t·D_t⁻¹ (mod q) whenever gcd(q, t!) = 1.

Symmetry: s_k = 2ᴺ − s_{N−1−k}. So every k uses target t_k = min(k, N−1−k) ≤ N/2.

### 4.3 Splitting each modulus
Factor m_k = Π p^e. Let t = t_k.

| part | condition | how s_t mod part is obtained |
|---|---|---|
| **main** | product of all p^e with p > t | ART item (target t, modulus q) |
| **Lucas** | p ≤ t, p ∥ m_k | Lucas: s_t mod p is a polynomial in digit data (below). The only non-trivial inputs are s_r and C(N,r) mod p with r = t mod p < p. These come from an ART item (target r, modulus p). All k with p ∣ m_k share one or two such items (k ≡ c_p mod p). |
| **p-adic** | p ≤ t, p^e ∥ m_k, e ≥ 2 | p-adic Lucas recursion (below), O(e²·p·log_p N) word ops per target, no big numbers |

Each part's result is added to a fixed-point accumulator as ±frac(X·s·a/q), with
a = (m_k/q)⁻¹ mod q. So nothing has to be stored between parts.

**Lucas formula** (p prime, digits N = Σ N_i pⁱ and t = Σ t_i pⁱ, with
G_i(x) = Σ_{y<x} C(N_i, y) mod p):

  s_t ≡ Σ_i [Π_{u>i} C(N_u,t_u)]·G_i(t_i)·2^{Σ_{u<i} N_u} + Π_u C(N_u,t_u)   (mod p).

For i = 0, C(N_0,y) ≡ C(N,y) for y < p (Lucas with a one-digit y). So G_0(t_0) = s_{t_0} − C(N,t_0)
and C(N_0,t_0) = C(N,t_0), which both come from the ART item. For i ≥ 1, N_i ≤ N/pⁱ, so those rows
are computed directly in O(min(p, N/p)) per prime. **[proved]**: this is Lucas' theorem plus a
lexicographic split of {j ≤ t}.

**p-adic recursion** (the fix for p² ∣ m_k). Write N = pK + N₀ and
g(x) = ((1+x)^p − 1 − x^p)/p ∈ Z[x]. Then

  (1+x)^N = (1+x)^{N₀}·((1+x^p) + p·g(x))^K ≡ Σ_{i<e} C(K,i)·pⁱ·(1+x)^{N₀}g(x)ⁱ·(1+x^p)^{K−i}  (mod p^e).

Put h_i = (1+x)^{N₀}gⁱ. It has degree < (i+1)p, prefix sums H_i. With t = pT + r:

  s_t(N) ≡ Σ_{i<e} pⁱC(K,i)·[ h_i(1)·s_{T−i−1}(K−i) + Σ_{d=0}^{i} H_i(dp+r)·C(K−i, T−d) ]   (mod p^e),
  C(N,t) ≡ Σ_{i<e} pⁱC(K,i)·Σ_{d=0}^{i} h_i[dp+r]·C(K−i, T−d)   (mod p^e),

where the i-th inner quantities are only needed mod p^{e−i}. The recursion is on rows ≈ N/p,
depth log_p N, with base case N < p (all denominators invertible). For e = 1 it *is* Lucas'
theorem. **[proved]**: the binomial expansion, then collecting coefficients. The prototype checks
it against exact binomials for 400 random (p, e, N, t) cases with p ≤ 101 and e ≤ 4.

### 4.4 Chunked accumulating remainder tree (the "binary splitting on numbers of size O(m)")
Sort all ART items by target. Cut the sorted list into chunks whose modulus product
Q = Π q has ≈ m bits. For each chunk:

1. Build the product tree of its moduli.
2. **Prefix:** advance (1,1,1) to the chunk's first target t₁ modulo Q. Use groups of
   g = ⌊m / log₂N⌋ consecutive steps; each group's (α, δ, τ) is computed *exactly* by binary
   splitting (numbers ≤ ≈m bits), then folded into the state with three products and a
   reduction mod Q.
3. **Descent:** at a tree node covering targets t_l..t_h with state X (at t_l, mod Q_node), the left
   child gets X mod Q_left. The right child gets (X mod Q_right) advanced from t_l to t_mid, the
   same way as step 2 but mod Q_right.
4. At a leaf, output (P, T, D) mod q.

In a memory-faithful implementation (the prototype does not do this, §7), items are generated in
order as a stream. Main items come out naturally in target order (t = 0..N/2, using both k = t and
k = N−1−t). Their moduli are factored chunk by chunk with a segmented sieve. Lucas items get their
own chunks, taken in prime order: a chunk's targets then spread over [0, N/2], which costs the same
as one main chunk. Their consumers loop over the arithmetic progression k ≡ c_p (mod p).

## 5. Complexity **[proved, modulo the stated model]**

Model: w = Θ(log n)-bit words, M(b) = O(b log b loglog b) bit operations for b-bit
multiplication, i.e. O((b/w)·log b·loglog b) word operations.

### 5.1 ART
* Item bits: main ≤ N·log₂(2(M+1)N) = O(N log n); Lucas ≤ 2Σ_{p≤N} log p = O(N). So there are
  O(N log n/m + 1) chunks.
* Prefix per chunk: ≤ N/2 steps in ⌈N log N/m⌉ groups, each O(M(m) log m) → O(N log n · log²m · loglog m / w) word ops.
* Descent: spans of all nodes on one level sum to at most the chunk's span. Summed over chunks,
  spans total ≤ N/2. Descent is therefore O(N log n · log³m) bit ops overall, which is lower order.
* **Total ART: O(N² log n · log²m · loglog m / m) word ops.**
* **Memory:** Q, a 3-component state and one group's binary-splitting stack are O(m) bits each.
  The full product tree is O(m log L). You can bring that down to O(m) by recomputing nodes or
  shrinking the chunk budget by log m. The prototype keeps the tree.

### 5.2 Lucas and p-adic parts
* Lucas: tables O(Σ_p min(p, N/p)) = O(N loglog N). Queries O(log_p N) per (k,p) pair. Total O(N log N loglog N).
* p-adic: for each odd p, the k with p² ∣ m_k form an arithmetic progression of difference p², so
  there are ≤ N/p² + 1 of them. **This bound is rigorous.** Each costs O(e²p log_p N). Summing over
  p ≤ √(2(M+1)N) gives O(N log N loglog N + MN). The MN term is at most the cost of the B part.
  Memory O(p) as implemented. O(1) is possible by streaming the h_i coefficients.

### 5.3 The rest
X mod m_k, 2ᴺ mod q and partial-fraction inverses: O(N log n) word ops. Factoring by segmented
sieve: O(N loglog N + (N log n/m)·√(MN)), lower order.

### 5.4 Balancing
B costs Θ(MN log n). C costs Θ(N² log n log²m loglog m/m). Take
M = Θ(max(4, N log²m loglog m / m)). Then ln(2eM) = ln(n/m) + O(loglog n) and
N = Θ(n/log(n/m)) for m ≤ n/polylog. So

  **T(n, m) = O( n² · log n · log²m · loglog m / (m · log²(n/m)) ) word operations, memory O(m log m) bits (O(m) with care).**

For m = n^Θ(1), log²m = Θ(log²n), and this is **exactly Gourdon's (11)**:
O(n² log³n loglog n / (m log²(n/m))). At m = √n it gives O(n^{3/2} log n loglog n), his first
special case. The log²(n/m) denominator is the fingerprint. It comes from N² with N ∝ n/log M and
M ∝ n/m, i.e. from balancing B against a binary-splitting C part. We're fairly confident this is
the algorithm he had in mind. His handling of small primes may have differed; a loglog from
Σ1/p (as in his Lemma 1) would fit the same bound.

## 7. Caveats (be honest)

* **Bookkeeping memory in the Python prototype is O(N), not O(m).** The factor table, the item
  list and the X_k list are all held in full. Only the bignum working set honours the budget (the
  `peak~` column is an upper bound on it: tree + state). Not fixed in the prototype itself.

  **Update (2026-09-23, Rust port `src/nthdigit2.rs`): the streaming construction this section
  describes is now implemented**, and it removes the global factor table and global item list
  entirely: `stream_needs_and_chunks` makes one sequential pass over target space, deciding
  Main-item chunk boundaries by running bit-count alone (items are regenerated per chunk by
  `art_chunk_by_range`, re-factoring just that chunk's target window, never held globally), and
  small-prime (`p <= sqrt(max m_k)`) Lucas/p-adic needs are collected into `O(pi(sqrt(max
  m_k)))`-bounded maps and resolved by "small primes in their own pass with their own small ART"
  exactly as this section proposed. **One piece did not reduce to a bounded structure**: a `k`'s
  leftover factorisation cofactor (the single prime factor of `m_k` above `sqrt(max m_k)`, if
  any) is sometimes itself `<= t_k` and needs Lucas treatment, but — unlike a small sieve prime —
  it's essentially unique to that `k` (or its mirror), not shared by a residue-class arithmetic
  progression the way `p <= sqrt(max m_k)` primes are, so it can't be resolved by the same
  bounded per-prime iteration. Measured at n = 1e5..1e7, this affects roughly 15-40% of `k`
  (rising with `n`, since `N` grows relative to `sqrt(max m_k)`), and is now kept as a single flat
  `Vec<(p, k, t)>` (24 bytes/entry) rather than inside the old per-`k` factor table + item list +
  several `HashMap`s — an order of magnitude smaller in practice (measured peak RSS: see
  `docs/nthdigit.md`'s updated Theorem-2 benchmark table) but still genuinely `O(N)`, not `O(m)`.
  Eliminating it fully would need an external (disk-backed) sort of these needs by target, or a
  cleverer classification that doesn't require computing the cofactor's value before knowing
  whether it counts as "small"; neither is implemented.

  **Update 2 (2026-09-23, same day, a memory-profiling follow-up): the streaming paragraph above
  overstated how bounded its own `HashMap`s were.** Measured peak RSS at n=1e7 was still 447 MiB
  after streaming — nowhere near the tens-of-MiB the "O(pi(sqrt(max m_k)))-bounded maps" claim
  above implies, and far more than the cofactor `Vec`'s own tens-of-MiB size could explain.
  Profiling (`--features mem-profile`, a counting global allocator + explicit per-structure
  sizing — see `src/nthdigit2.rs`'s module docs) at n=1e6/3e6 found two real, distinct bugs:
  (1) `PadicBinom`'s recursion memo tables (`memo_s`/`memo_c`) were memoising across an entire
  prime's worth of top-level queries instead of within one query's recursion tree, growing to
  roughly 10x the query count for small primes — this alone was ~40 of ~58 MiB at n=1e6, by far
  the single largest contributor found; (2) `lucas_small`/`padic_small` genuinely did cost
  `O(N loglog sqrt(max m_k))` words (Mertens' third theorem), not `O(pi(sqrt(max m_k)))`, because
  each `HashMap` key held a `Vec` of *every* matching `(k,t)` pair rather than the compact
  arithmetic-progression range each key's matches actually form. Both fixed: the p-adic memo is
  cleared before each top-level query, and the need-lists became `SideRanges` (two `u64`s per
  key — first/last `t` seen — with consumers regenerating `(k,t)` by walking the range at its
  known step). Peak RSS at n=1e7: 447 MiB -> 69 MiB. `cofactor` is now, empirically, the
  dominant *named* remaining term (as this section originally predicted it eventually would be),
  but at tens of MiB rather than the ~450 the other two bugs were masking it under. See
  `docs/nthdigit.md`'s Theorem-2 section for the full before/after/now benchmark table.
* The p-adic tables are O(p) words, and p can reach √(2(M+1)N) *in principle*. In the Rust port,
  p-adic treatment only ever applies to primes `<= sqrt(max m_k)` (a prime above that bound
  divides `m_k` to at most the first power, by construction — see above), so its p-adic tables'
  peak is `O(sqrt(max m_k))`, not `O(√(2(M+1)N))` or `O(N)`. Streaming the coefficients further
  (within a single large prime's table) is still not implemented, but isn't needed at the `m`
  values tested.
* Python per-leaf overhead is a large constant in the ART. B is numpy-vectorised; C is not. So the
  prototype's best M is tuned to Python, not to a native build. A Rust/C port with GMP
  (`rug`) should be much faster per leaf. We'd expect the speedup over Theorem 1 to grow like
  m/polylog.
* The asymptotic gain needs subquadratic multiplication. At m ≈ 10⁴ bits GMP is in the
  Karatsuba/Toom range, so part of the measured gain is simply packing log n-bit factors into
  64-bit limbs.
* B's float64 + fsum accumulation limits the prototype to about 12 correct digits after position n.
* Theorem 2's "O(m) memory, n^ε ≤ m ≤ n": our bound needs m ≤ N log n for the chunk count formula.
  Near m ≈ n it degenerates to the Õ(n) binary-splitting regime, as Gourdon says.

## 8. Verdict

* **Proved:** a concrete algorithm with O(m log m)-bit working set (O(m) with standard care). It
  achieves Gourdon's Theorem 2 bound in the word-operation model for m = n^Θ(1). The division
  problem is fully handled: partial fractions + Lucas + a p-adic Lucas recursion. No factorials
  modulo large primes are needed.
* **Measured:** correct digits at n = 10⁴ … 1.28·10⁶. Scaling exponents are consistent with
  n^{1.5}/polylog at m ∝ √n and with 1/m at fixed n, until non-ART overheads dominate. The
  prototype beats a C Theorem-1 implementation from about n ≈ 4·10⁴ upward, despite being Python.
